# Почтовое бюро

Учебный сервис на Django 5.2 и SQLite. В нём можно вести список получателей,
готовить письма, задавать окно отправки и просматривать результаты доставки.

## Быстрый запуск

Требуется Python 3.11–3.14. Из корня проекта в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

Откройте http://127.0.0.1:8000/. Настройки из `.env` необязательны для локального запуска:
по умолчанию используется SQLite, часовой пояс Москвы и вывод писем в терминал.
Пароли, база данных и локальное окружение исключены из Git.

## Как показать проект

1. Зарегистрируйтесь. Откройте ссылку, напечатанную в терминале с сервером, и нажмите
   «Подтвердить адрес». Войдите с логином и паролем. Ссылка действует 24 часа.
2. Создайте получателя и письмо. В разделе «Рассылки» создайте рассылку:
   установите начало немного позже текущего времени и окончание позже начала.
3. Откройте рассылку после её начала и нажмите «Отправить письма».
   Результаты видны в журнале рассылки и в разделе «Отчёт». Ручной запуск можно
   повторить в пределах окна: каждый запуск создаёт новые попытки.
4. Чтобы проверить отказ, попробуйте отправить письма до начала или после окончания.
   Чтобы проверить восстановление пароля, откройте «Забыли пароль?» на странице входа;
   ссылка для смены пароля также появится в терминале.
5. Для проверки прав зарегистрируйте и подтвердите второй аккаунт. Назначьте его
   менеджером из второго терминала:

```powershell
.\.venv\Scripts\python.exe manage.py grant_manager LOGIN
```

Менеджер видит чужие рассылки и получателей. Он может остановить отправку
и заблокировать обычного пользователя, но не может изменять, удалять или отправлять
чужую рассылку. Менеджер не может заблокировать себя, другого менеджера или администратора.
Раздел «Отчёт» показывает только попытки текущего пользователя.

Также можно запустить рассылку с компьютера, на котором развёрнуто приложение:

```powershell
.\.venv\Scripts\python.exe manage.py send_mailing 1
```

## Настоящая почта

В `.env` укажите `EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend`,
параметры `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`,
`DEFAULT_FROM_EMAIL` и режим шифрования своего провайдера. TLS и SSL
нельзя включить одновременно. Перезапустите сервер. Почтовый сервер сообщает
о принятии письма, а не о том, что адресат его прочитал или что оно дошло до входящих.
При использовании консольного режима фактической доставки нет.

## Правила и устройство

- `mailings/models.py` — получатель, письмо, рассылка и попытка отправки. Адрес
  получателя уникален во всей базе, без учёта регистра. Начало и окончание обязательны;
  при создании и переносе начала нельзя выбрать прошедшее время. Можно менять
  состав активной рассылки, если время начала не меняется.
- `Mailing.update_status()` сравнивает текущее время с расписанием и сохраняет
  статус только при изменении. Метод вызывается из `get_object()` при просмотре.
  Обе границы времени входят в интервал отправки. Отключение менеджером хранится
  отдельным флагом и не сбрасывается при пересчёте статуса.
- `mailings/services.py` — общая логика запуска для сайта и команды. На каждого
  получателя вызывается `send_mail()`, а результаты сохраняются через
  `bulk_create()` пачками до 500 записей. Ошибка у одного адресата не мешает
  отправке остальным.
- `accounts/` — регистрация с подписанной ссылкой, роли и модерация.
  Вход, выход и сброс пароля используют встроенные представления Django.
- `mailings/metrics.py` — серверный кэш сводки и личных отчётов. Сводка
  учитывает ближайшую смену статуса, а записи инвалидируются после сохранения
  изменений. Гостевая главная может кэшироваться браузером до 10 секунд;
  страницы с личными данными и отчётами передаются с `no-store`.
  Для учебного запуска в одном процессе используется LocMemCache.

## Проверка

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test
```

Тесты создают временную базу и используют почтовый бэкенд в памяти.
Они проверяют доступ по ролям, валидацию расписания, границы отправки, запись
попыток, подтверждение адреса, смену пароля и работу кэша.

Документация: [аутентификация Django](https://docs.djangoproject.com/en/5.2/topics/auth/default/)
и [кэширование Django](https://docs.djangoproject.com/en/5.2/topics/cache/).
